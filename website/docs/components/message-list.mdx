## 用法

```tsx
<View style={{ height: 480 }}>
  <MessageList
    items={messages}
    keyExtractor={(item) => item.id}
    renderItem={(item) => <Message text={item.text} />}
    hasEarlier={hasEarlier}
    onRequestEarlier={loadEarlier}
  />
</View>
```

## 行为与接入

父容器必须提供有界高度，避免嵌套在同方向的无界 ScrollView 中。数据类型由调用方决定，`renderItem` 可以返回 Message 或任意自定义行。

`contentContainerStyle` 只调整列表内容布局，可用于页面消息留白和空态居中；`style` 仍只调整外层视口。`keyboardDismissMode` 支持 RN 的 `interactive`，默认 `on-drag`。`showsVerticalScrollIndicator` 默认 false。离开末尾后的返回入口采用 36 的视觉圆、44 的触达区，中文可访问名称仍是“回到最新消息”。

更新消息时创建新的 `items` 数组，并保留未变化项的引用。列表会复用未变化行；流式场景可用 `useCallback` 保持 `keyExtractor`、`renderItem` 和 `renderSeparator` 稳定。行依赖选中状态等外部数据时，通过 `extraData` 通知更新；不能原地修改 `items` 后期待列表自动识别变化。

默认从 `initialPosition="end"` 开始，`followOutput="whenAtEnd"` 仅在用户位于末尾时跟随新增内容；阅读历史时不会强行跳到最新。纯前插保持当前可见内容的位置。

空列表中的动态 header 和 empty 不参与消息锚点保持，避免加载占位切换时产生原生滚动偏移；消息到达后恢复位置保持。

历史入口需要同时提供 `hasEarlier` 与 `onRequestEarlier`；加载状态由 `loadingEarlier` 控制。滚动不会自动发起历史请求。ref 的 `scrollToEnd()` 可显式回到末尾。切换会话时用 React `key` 重建实例。

## 发送后的顶锚

`ref.anchorToItem(key, { topOffset: 8, animated: true })` 以稳定的 item key 指定正文起点。`topOffset` 默认 0，`animated` 默认 true。组件先取得真实 cell 与正文相对位置（包含外部 header、内容留白，避开 `renderSeparator`），必要时撑开列表底部，等原生内容尺寸确认可达后再定位。

```tsx
const id = createLocalMessageId();
setMessages((current) => [...current, { id, text }]);
listRef.current?.anchorToItem(id, { topOffset: 8 });
```

请求可以先于本次受控 `items` 提交。后续同项正文增长不会追到尾部，视口或目标前方布局变化则保持其顶端位置。屏外项先通过 FlatList 公开定位入口进入渲染窗口，最终位置仍以真实测量为准。Jest 的布局事件测试不代替设备长列表与键盘验证。

顶锚期间暂停前插位置补偿，避免两个滚动机制重复调整；用户拖动、调用 `scrollToEnd()`、目标出现后又被移除，都会结束本请求并撤下撑高。删除后再加入同 key 不会复活旧请求；需要新定位时再次调用。回到末尾等待撑高撤除后的真实内容尺寸，不落到之前制造的空白。`followOutput` 继续单独决定没有显式顶锚时的末尾跟随。

定位点是 `renderItem` 返回内容的起点。一个 item 包含多个子消息时，调用方应选中确实以目标消息开头的 item；组件不猜测业务卡片或组内哪一段是最新用户输入，也不生成消息身份。
